# 智能屏幕识别与最优路径（smart-screen-nav）

> **一句话**：让 AI 在 Android 真机上"看见屏幕、规划最优路径、一次点对"，并把每次成功操作沉淀成可复用的经验，**越用越准、越用越快**。

---

## 〇、使用说明（给使用者看，怎么用这个技能）

> **本技能的三条铁律（用户偏好，必须遵守）**：
> **① 省 Token 优先**：只输出必要信息、紧凑高效、按需展开。默认给"一句话结论 + 最短路径 + 关键坐标/命令"，需详情才展开完整 dump/日志；绝不整段重复截图识别文本。
> **② 精准智能兼容**：坐标/路径判断依赖**实时**界面（动态取坐标、绝不写死）；兼容不同设备、不同 App 版本；对偏离先 `env.py check` 辨因，不盲目重试。
> **③ 短思考·快响应·效果佳**：默认走**最短路径**一次点对（不绕弯、不假设、不空谈），命令直达优先、可复用剧本直接秒执行；快且准、不牺牲能力。

### 短思考决策速查（一步到位，不绕弯）
> - 能**命令直达**（am start 等）→ 直接命令，不点 UI；
> - 必须 UI → **dump 拿实时坐标**→ 点击 → 截图确认；
> - 打开文件 → `OpenFileActivity` 一步定位；
> - 看到弹窗 → 先识别再选；
> - 操作与上次不一致 → 先 `env.py check` 辨因（升级/UI变化），别盲目重试；
> - 命中 Playbook → 直接照执行，不再重新思考路径。

### 这个技能能做什么
- **让 AI 自动控制屏幕**：点击、滑动、导航、打开文件、定位到指定位置。
- **自动规划最优路径**：能用一条命令直达的，绝不让它一步步点 UI。
- **自动沉淀经验**：走通一次后记住路径，下次遇到同一界面**免思考秒执行**。

### 怎么使用（三种触发方式）
1. **自然语言直接说**：`帮我打开 XX 并定位到第 N 行` / `帮我在手机里找到/打开 XX`。
2. **纠正/指导**：当它点错、走到错误界面，按下方【二、如何指导 AI 纠正】给反馈。
3. **让我积累**：遇到"经常重复的固定动作"，可要求我「走通后存成剧本」，下次就秒执行。

### 它会怎么工作（你可以期待的行为）
- 每一步操作前，它都会先**读取当前屏幕真实结构**拿到实时坐标，**绝不写死坐标**；
- 每步关键操作后**截图确认**是否到达预期界面；
- 优先用**命令直达**（如 `am start`）替代繁琐点击；
- 被 Operit 抢占前台、碰到弹窗时，会**停下来确认**而不是盲目连点；
- 操作成功后会**把正确路径顺手沉淀**，下次更快。

## 一、核心原则（最重要的三条）
1. **动态取坐标**：任何点击/滑动前，先用 `uiautomator dump` + `grep bounds` 拿到元素的**实时**坐标，取中心点点击。**绝不使用写死的坐标**（不同机型、不同状态坐标都会变）。
2. **每步截图确认**：关键操作后必 `screencap` 确认是否进入预期界面，**不要盲目连点**。
3. **命令直达优先**：能用一条命令（如 `am start` 带对组件）完成的事，绝不用多步 UI 点击。

---

## 二、如何指导 AI 纠正（关键：点错 / 路径不对时怎么办）

> **这是本技能最重要的"自我进化"入口**：你每一次纠正，都会让 AI 把"错误路径"记进避坑、把"正确路径"重生成为经验，下次不再重犯。

### 你只需要这样反馈（三步模板，说清楚就行）
```
① 现象：  它停在哪 / 点到了哪 / 报了什么错
② 期望：  你希望它到达哪里 / 点哪个按钮 / 或用更直接的命令
③ 提示：  可选，比如"用命令直接打开，别一步步点" / "按钮在屏幕左侧"
```
**示例**：
> "你点错了，停在『打开方式』弹窗了。我只要跳转到第 124 行，你应该点『文本编辑器』那个选项，不是点『打开』。以后直接跳到 124 行再确认。"

### AI 收到纠正后必须做的动作（写入纪律）
1. **先复述目标、dump 当前屏幕**——确认自己所在界面与预期界面的**真实差异**；
2. **找根因**：点错了控件 / 没进预期界面 / 被 Operit 抢前台 / 用了过时坐标或旧路径；
3. **优先改方案**：① 能命令直达就用命令；② 其次换更稳的组件（`content-desc`/`clickable`）；③ 最后才改坐标，且必须用**当时 dump 出的实时坐标**；
4. **走通后立即沉淀**：把"新正确路径"写入经验库、把"错误路径"写进避坑/禁用，让这次纠正**固化成长期经验**；
5. 若反复仍失败，**停止盲目重试**，改为向你确认或引导你点一步。

### 关于"经验升级"的规则
- 你**纠正一次并成功** → 我要把"正确方案优先、错误方案禁用"写进经验库；
- 同一界面**多次纠正** → 说明路径不稳，我应该换更可靠的方案或提醒你当前环境需人工介入；
- 只有**真正验证成功**的方案才沉淀；尝试失败的不记，避免污染经验。

## 三、标准识别流程
```bash
# 1) 导出当前界面结构
uiautomator dump /sdcard/ui.xml

# 2) 查找目标元素的文本/描述及其坐标
grep -oE 'text="目标文字"[^>]*bounds="\[[0-9]+,[0-9]+\]\[[0-9]+,[0-9]+\]"' /sdcard/ui.xml

# 3) 取 bounds 中心点，用 input tap 点击
input tap <x> <y>
```
- 目标元素可能是 `text="..."`，也可能是 `content-desc="..."`（无文字图标）。先 `grep -oE 'text="[^"]+"'` 看有哪些可点项，再定位。
- 取控件：优先找 `clickable="true"` 的节点。
- 坐标规律：`bounds="[x1,y1][x2,y2]"` → 中心点 = `((x1+x2)/2, (y1+y2)/2)`。

## 四、最常用的“打开文件/定位”命令（路径最优）
```bash
# 用 MT 定位到某文件/目录（推荐，一步到位）
am start -a android.intent.action.VIEW \
  -d "file:///storage/emulated/0/<目录URL编码>/<文件名URL编码>" \
  -n bin.mt.plus/bin.mt.plus.OpenFileActivity
```
- **必须**用 `OpenFileActivity`（MT「打开文件·定位」），不要用 `.Main`（会弹「选择打开方式」菜单）。
- **不要**加 `-t <mime>`，否则弹系统「选择打开方式」而非定位。
- 中文路径必须完整 URL 编码（`文本文档` = `%E6%96%87%E6%9C%AC%E6%96%87%E6%A1%A3`；漏字会 `ENOENT`）。
- 目录定位在**末尾加 `/`**，文件定位到完整文件名。

## 五、关键避坑（实战总结）
1. **Operit 会抢占前台**：在 Operit 对话里执行 `am start` 拉起其他 App 后，Operit 的 MainActivity 可能很快把前台抢回，导致操作被打断、界面跳动。
   - **对策**：拉起目标 App 后**立刻**（`sleep 1` 内）`screencap` 确认；若被抢回，**不要反复 `am start`**（会切断用户已打开的窗口），改用别的策略或引导用户手动点一步。
2. **「打开方式」弹窗**：MT 打开 `.md`/文本文件会弹「打开方式 / 取消 / 3/10文档 / 文本编辑器 / 打开」。直接点「**文本编辑器**」那一行即可进入；若未进入，再点「**打开**」确认。
3. **跳转指定行**：进入文本编辑器 → 点右上「≡」菜单 → 「**跳转到指定行**」→ 点击输入框 → **先 `keyevent 67` 清空默认行号**再 `input text`（否则变成 `1241`）→ 点「确定」。
4. **输入法**：系统默认讯飞会把英文当拼音候选；注入英文/符号前临时 `settings put secure default_input_method com.android.inputmethod.latin/.LatinIME`，再用 `input text`，完后再切回。
5. **back 回主界面**：在聊天页按 `back` 会退出到桌面；要回 Operit 主界面用 `am start -n com.ai.assistance.operit/.ui.main.MainActivity` 或点左上「菜单」。

## 六、通用“最优路径”清单（记忆口诀）
- 能命令直达 → 不用 UI 多步；
- 必须 UI 点击 → 先 dump 拿坐标 → 点击 → 截图确认；
- 打开文件 → `OpenFileActivity` 一步定位；
- 看到弹窗 → 先识别弹窗内容再选，别乱点；
- 被抢前台 → 停手，确认或引导用户一步。

### 使用纪律（AI 须遵守）
1. **操作屏幕前**：先 `exp.py query "<场景关键词>"`，命中则**直接复用**成功路径，避免重复踩坑。
2. **操作成功后**：若发现新的正确路径/坐标/更优方案或新坑，必须 `exp.py add` 追加（或更新既有条目）。
3. 经验库与 Skill 同步：Skill 变更后，优先在经验库补一条"本次修正"。
4. 只有"真正验证成功"的路径才写入；单纯尝试未成功的不要写，标记为待验证。

### 七.5 Playbook 免思考层（环境指纹 → 秒执行，终极形态）
> 目标：**同一环境第二次别再"想"，直接照抄最优路径执行**，把操作时间压到最低。
> 适合：经常重复的"调起某 App/进入某界面/定位某文件"这类固定动作。

**机制**：把「当前界面特征(env_sig)」与「最优命令剧本(playbook)」**强绑定**存储；下次先 `dump` 当前界面 → 提取特征 → `match` → **命中即整段执行，免推理**。

```bash
cd "/storage/emulated/0/Download/Operit/skill-data/smart-screen-nav/经验库"
# 第一/次成功走通后，沉淀剧本：
python3 pbook.py add "<剧本名>" "<场景>" "<环境特征;用;分号;分隔>" "<命令剧本;多行;用\\n>"
# 下次：dump提取当前界面特征 → match → 命中直接执行
python3 pbook.py match "<当前界面特征;分号分隔>"
python3 pbook.py list                       # 已有剧本
```

**使用纪律**：① 仅保存**已验证成功**的剧本；② match 匹配度需≥2个特征重叠才算命中；③ 命中后**直接照执行**，别再从头思考路径；④ 界面变化导致失败时，重新走通并 `add` 覆盖更新。

### 七.6 版本/环境指纹（版本变化检测 —— 操作异常时的第一反应）
> **背景**：App 升级、系统升级、UI 改版会让旧经验/剧本失效。若不同步，AI 会反复踩坑。

**核心规则（AI 必须遵守的判断链）**：当某次操作结果**和以往成功经验不一致**时，**先查版本指纹再动手**：
```
① 抓当前环境版本：系统(ro.build.version.release/sdk)、目标App(versionName)
   # 安卓shell: getprop ro.build.version.release; dumpsys package <包名>|grep versionName
② env.py check <经验key> <当前AppVer> <当前OSVer> <当前sdk>
   ├─ App版本变了  → App升级导致UI变化 → 旧路径失效 → 重新走通并绑定新版本
   ├─ 系统版本变了 → 系统升级影响权限/组件 → 重验并更新经验
   └─ 版本都没变   → 纯同版本UI微调 → 重新dump定位即可（不用动版本指纹）
③ 重新走通成功后，env.py save 刷新该经验的新版本指纹（完成升级）
```

```bash
cd "/storage/emulated/0/Download/Operit/skill-data/smart-screen-nav/经验库"
python3 env.py save "<经验key>" "<App名>" "<App版本>" "<OS版本>" "<SDK>" "<设备/构建>"
python3 env.py check "<经验key>" "<当前App版本>" "<当前OS版本>"   # 异常时先跑这个
python3 env.py list
```

**纪律**：① 每条"会受版本影响"的经验保存时，**必须同时记录版本指纹**；② 操作异常先 `check`，**别急着盲目重试**；③ 升级后重新走通并**刷新版本指纹**，才算真正完成经验升级。

### 七.7 通用经验的分发与删除（多用户导入必读）

### 七.8 通用/个人标记 + 智能归类 + 单备份分发（多用户积累闭环）
> **目标**：通用经验随包累积分发、个人经验留本地；打包最多留一个备份。

#### 1) 通用 vs 个人（AI 智能判定）
- **通用**：跨设备/跨用户都成立（MT定位、输入法、抢前台、升级纪律等）→ 随包的 `generic-exp.seed` 累积；
- **个人**：依赖本机数据/习惯（某私有目录、某账号、某固定设置）→ 留本地，**不进种子、不随包**。
- **智能归类纪律**：每次沉淀成功经验时，AI 判断"换台设备是否同样成立"——成立标`通用`，否则标`个人`；不确定的，用户可随时改。

```bash
python3 exp.py add <场景> <路径> <避坑> <可复用度> [通用|个人]   # 添加时直接指定类型
python3 exp.py tag <id> 通用|个人                              # 事后改类型
python3 exp.py list          # 会显示每条的类型(通用/个人)
```

#### 2) 种子累积导出（打包分发，个人不带走）
```bash
python3 exp.py seed ./generic-exp.seed   # 只把【通用】经验累积进种子(按场景去重累加)
```
> 每次升级总结出的新通用经验都会**不断累积**到种子，下次打包分发时全带上。

#### 3) 单备份打包（升级即删旧包，最多一个）
```bash
python3 pkg.py make    # 生成分发包(含 SKILL.md + 通用种子 + 脚本)，先删旧包再打新包
python3 pkg.py list
```
> 分发包位置：`Download/Operit/skill-data/smart-screen-nav/发行/smart-screen-nav-skill.zip`
> **单备份纪律**：每次 `make` 先删除该目录下所有旧 `*skill.zip`，保证**最多只保留一个备份**；下一个升级生成新包时，上一个备份即被替换。

## 八、版本更新纪律（每次升级必须遵守）

> **每次升级必须先更新本使用说明文档**：让描述保持清晰、易懂、专业，方便其他人（和其他 AI 会话）看一眼就能上手用、知道怎么用、知道怎么纠正。改动集中在 "〇、使用说明"与"二、如何指导 AI 纠正"两节。

1. 先删旧 zip → 重新生成 `<skill>-skill.zip`（内容 = 生效目录最新 SKILL.md）；

## 九、方案选择机制与归类纪律（设备可达性执行策略体系）

> **背景**：屏幕操作存在 5 种"抵达目标"的执行策略（见 `/sdcard/文本文档/设备可达性执行策略体系.html/.md`）。用户可在 Operit 选择任意一种方案；AI 执行屏幕任务时按所选方案走；用户不选则默认"智能混合(择优)"。

### 9.1 五种方案（策略枚举）
| 模式 | 名称 | 定位 | 执行手段 |
|---|---|---|---|
| `p1` | 系统框架 API 直调 | 命令直达最优先 | `am start` / `pm` / `dumpsys` / UIAutomator 框架等 |
| `p2` | 预置脚本快路径 | 命中剧本即整段执行 | Playbook(`pbook.py`) 命中优先，免推理 |
| `p3` | 全量人工注入 | 强制拟人 | **所有交互走 `input` 注入(随机化)，禁用命令直达** |
| `p4` | 混合分层 | 编排壳 | `p2` 优先 → 无脚本回退 `p3` |
| `p5` | 虚拟显示注入 | 兜底隔离 | 虚拟显示(需部分 root) |
| `auto` | 智能混合(默认) | 择优调度 | 见 9.4 判定链 |

### 9.2 选择粒度（全局默认 + 单次任务临时覆盖）
- **全局默认**：`strategy.py set <mode>`，持久化，直到用户下次更改。
- **单次临时**：`strategy.py temp <mode>` 只覆盖本次任务；任务结束可 `strategy.py clear` 清除回到全局。
- **优先级**：临时 > 全局 > 默认(auto)。

### 9.3 执行入口提示时机（省 Token 铁律）
- **多步骤屏幕操作任务**（需点击/滑动/导航等 ≥2 步）+ 当前模式为 `auto` → **任务开头轻量问一次**：一句话列出可选方案，用户可回车走默认。
- 当前模式**已指定**（非 auto）→ **不再询问**，直接按该模式执行，直到用户更改。
- **单步命令直达任务**（如定位某文件）→ **不打扰**，按当前模式执行即可。
- 用户可能以自然语言临时切换（如"这次用全量人工"），AI 应调用 `strategy.py temp` 记录，不污染全局。

### 9.4 auto 判定链（固化，不纠结）
```
① 能命令直达(am start/pm 等)且属系统能力 → p1
② 否则 命中 Playbook(pbook.match ≥2特征) → p2
③ 否则 多步 UI 且需拟人/通用兜底 → p3
④ 组合调度壳 → p4 ；虚拟显示(需root) → p5(垫底, 未root先降级提示)
```
> **p5 特殊**：未 root 设备选择 p5 时，如实提示"需 root"，并**降级回 auto** 再按 9.4 走，不硬执行。

### 9.5 经验归类纪律（双维并存，互不设限）
- **维度①：方案归属 `strategy`** —— 每条经验沉淀时，AI 判断"这条经验适用于哪种方案执行"：
  - 只适用于命令直达 → `p1`；剧本型 → `p2`；需拟人注入 → `p3`；混合 → `p4`；虚拟显示 → `p5`；
  - **多用型** → 多值逗号标记（如 `p1,p3`）；**通用不限方案** → `auto`。
- **维度②：通用/个人 `type`** —— 承袭既有规则：跨设备成立→`通用`；依赖本机→`个人`。
- **两者独立**：方案选择**不**限制经验采集归类；用户选 p3 也能沉淀 p1 类经验（作为参考），只是执行手段严格按所选方案。
- 添加时 `exp.py add <场景> <路径> <避坑> [高|中|低] [通用|个人] [策略]`；事后可 `exp.py strat <id> <策略>` 修正。
- **跨方案参考**：所选方案优先，但其它方案经验可作为"提示/校验"参考，执行手段仍严格遵守所选方案。

### 9.6 调用命令汇总
```bash
cd "/storage/emulated/0/Download/Operit/skill-data/smart-screen-nav/经验库"
# 方案状态
python3 strategy.py list                       # 列5方案+当前生效
python3 strategy.py get                        # 读当前生效模式
python3 strategy.py set p3                     # 设全局默认

python3 strategy.py clear                      # 清除临时
# 经验方案归类

python3 exp.py strat <id> p3                   # 事后改方案
python3 exp.py list | grep 策略                # 按方案过滤查看
```
> **升级纪律**：本次升级须同步两处 `SKILL.md`（源 `skill-data/` 与生效 `skills/`）；新增脚本 `strategy.py`、经验库 `strategy.json` 位于外部路径，删 Skill 不丢失。
